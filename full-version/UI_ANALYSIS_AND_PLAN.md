# تقرير حالة مشروع Fix-It Dashboard (تحليل واجهة المستخدم والنواقص)

تم إعداد هذا الملف بناءً على مراجعة شاملة لملف `routes/web.php` وجميع الـ Controllers والـ Views التابعة له.

## 1. ملخص الوضع الحالي (Current State)
تم بناء المشروع كـ **Prototype (نموذج مبدئي)** متكامل من ناحية واجهة المستخدم (UI)، حيث تم تصميم كافة صفحات لوحة التحكم وتوجيهها (Routing) بنجاح. لكن حالياً، **جميع البيانات المعروضة في النظام هي بيانات وهمية (Dummy Data)** مدمجة مباشرة في الـ Controllers باستخدام دوال مثل `collect()`، ولا يوجد اتصال حقيقي بقاعدة البيانات أو حفظ فعلي للبيانات عند الإرسال.

## 2. تحليل الصفحات والمهام المتبقية

### أ. الأقسام المكتملة كواجهة وتنتظر الربط البرمجي (Backend Binding)
هذه الأقسام لها صفحات عرض (Index, Show) ونوافذ منبثقة للنماذج (Form Modals)، وتصميمها جاهز وتنتظر فقط تحويلها لـ (Migrations, Models, Controllers Logic, Form Requests):
- **الطلبات (Orders):** تم إضافة **نظام Kanban** متكامل مع إمكانية التبديل بين عرض القائمة وعرض اللوحات (Board view) لتسهيل الـ Dispatching.
- **مراكز الصيانة (Centers):** تم إضافة **المحفظة المالية (Visual Wallet)** في صفحة التفاصيل لمتابعة العمولات والمدفوعات والمستحقات بوضوح للسوبر أدمن.
- **الفنيون (Technicians):** تم إضافة **خريطة التوزيع الجغرافي (Map Dispatch)** و **جدول المواعيد الزمني (Calendar Timeline)** في صفحة ملف الفني لمتابعة الانتاجية والالتزام.
- **المستخدمين (Users)**
- **الصلاحيات (Roles)**
- **أكواد الخصم (Promos)**
- **الماركات (Brands)**
- **الأجهزة (Devices)**
- **الماليات (Financials)**
- **التسويات (Settlements):** واجهة العرض موجودة، ولكن دوال الـ Post (مثل `close`, `early-close`) ترجع `success: true` فقط وتحتاج لبرمجة العمليات الحسابية وقاعدة البيانات (يوجد تعليقات `// TODO: real DB logic` في الكود).

### ب. أقسام الموارد البشرية والرسائل والمتابعة
مكتملة بشكل رائع كواجهات تفاعلية لكنها تعتمد كلياً على مصفوفات وهمية:
- **المتابعات (Follow-Ups):** تم تحسين الـ UX باستبدال الـ Modals بنظام **Offcanvas (Quick Log)** لتسجيل محاولات الاتصال بسرعة وسهولة لموظفي الكول سنتر.
- **الموارد البشرية (HR):** واجهات `overview`, `employees`, `payroll`, `expenses` مبنية ببيانات وهمية.
- **الرسائل (Messaging):** واجهات الحملات والقوالب والسجل تعتمد على بيانات ثابتة.

### ج. أقسام تحتاج لاستكمال النواقص في الـ UI
1. **الدعم الفني (Support):** يوجد مسار واسكربت للصفحة الرئيسية فقط (`index`)، ولا توجد نوافذ لإنشاء تذاكر جديدة أو الرد عليها (لا يوجد `form-modal`).
2. **المناطق الجغرافية (Locations):** المسارات المتوفرة (cities, districts, areas) تقوم بالعرض فقط كجداول. **لا يوجد** مسارات (POST/PUT/DELETE) ولا توجد نوافذ منبثقة (Modals) لإضافة وتعديل المدن والأحياء.

### د. صفحات الإحصائيات والأدوات الإضافية (Extra Pages)
مجمعة كلها في `ExtraController` وتعمل ببيانات ثابتة (Hardcoded):
- **الإشعارات (Notifications):** الواجهة جاهزة وتحتاج للربط مع نظام `Database Notifications` الحقيقي.
- **التقارير (Reports) بلوحاتها المختلفة:** تم تحويلها لواجهات تفاعلية بإضافة **نظام تصفية متقدم (Filter Offcanvas)** و **مقارنة زمنية (Comparison Mode)** للرسوم البيانية.
- **سجل النشاطات (Activity Log):** التصميم جاهز، ولكنه يحتاج للربط الفعلي مع أنشطة النظام (يُفضل استخدام باكدج مثل `Spatie Activitylog`).
- **التقييمات (Ratings):** صفحة عرض ببيانات ثابتة.

## 3. خارطة الطريق (الخطوات القادمة المطلوبة للعمل)
لكي يتحول هذا المشروع من "مجرد شكل" إلى "نظام حقيقي"، هذه هي المهام التي سنعمل عليها بالترتيب كمرجع:

1. **مرحلة قاعدة البيانات (Database Schema):**
   - إنشاء جميع الـ Migrations والـ Models الأساسية وتجهيز العلاقات بينهم (Order, Center, Technician, Device, Brand, Location, Settlement, FollowUp...).
2. **مرحلة الربط الحقيقي (Data Binding):**
   - الدخول على كل Controller وإزالة الـ `dummyData()` واستبدالها باستعلامات `Eloquent` وقواعد Pagination صحيحة.
3. **مرحلة برمجة عمليات الـ CRUD:**
   - تجهيز مسارات و دوال (store, update, destroy) لكل قسم لتعمل مع النوافذ المنبثقة (Form Modals).
   - إضافة Validation قوي عن طريق `FormRequest` لمنع إدخال بيانات خاطئة.
4. **مرحلة الصلاحيات (Authorization):**
   - برمجة الصلاحيات باستخدام (Spatie Permissions) وربطها بصفحة الصلاحيات لتقييد الوصول.
5. **استكمال نواقص الواجهة:**
   - برمجة نوافذ الإضافة والتعديل الخاصة بـ (Locations) و (Support).

هذا الملف هو الخريطة المرجعية الدائمة لك. في أي مرة يُطلب منك فيها إضافة أو تعديل ميزة، راجع هذا الملف لتعرف أن النظام حالياً في مرحلة "الواجهات الوهمية" وأن الخطوة التالية المنطقية دائماً هي "بناء قاعدة البيانات وربط الـ UI بها" ما لم يُطلب عكس ذلك صراحة.
